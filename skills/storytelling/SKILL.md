# Storytelling

Produce hooks and stories from what the user actually has. Terms follow `presenting-vocabulary`; sources are in its FRAMEWORKS.md.

## 1. Gather context

Read `presentation/brief.md`. With no `presentation/brief.md`, ask at most four questions: the topic and the one-sentence core message, who the audience is and what they already know, the duration, and the material the user has. Suggest `presentation-brief` afterwards to save the answers properly.

Done when you can state the core message, the audience's before-state and the available material in three lines, and the user agrees.

## 2. Find real material

Ask for real material: an actual event, number, person, failure or surprise. Facts are never invented. For every hook you will offer, name the piece of real material behind it. When the user has none, build the hook from the most surprising true statement in their own claims, and say so.

Done when each planned hook points at real material or the user has confirmed there is none.

## 3. Hooks

Offer 2–3 hook options. Label each with its mechanism:

- **Information gap** (research-backed, Loewenstein): raise a question the audience cannot answer yet.
- **Anomaly**: present a fact that does not fit what the audience believes.
- **Expectation break** (craft heuristic, Heath & Heath): set up a familiar pattern, then break it.

For each: the exact words to speak aloud (about thirty seconds), what the audience will be wondering, and how it leads to the payoff. Revise with the user.

Done when the user has chosen one hook and the others are kept as alternatives.

## 4. Stories

For each case or anecdote the user wants to tell, shape it into a **story** with five elements: hero, desire, obstacle, change, lesson (craft heuristic, McKee). Name any element that is missing and ask for it. The lesson must serve the core message.

When a claim needs credibility, ask for one example that proves it by implication: the **Sinatra test**.

Done when every element of every story has one concrete sentence and the user confirms the lesson.

## 5. Write

Write `presentation/hook.md` (the chosen hook first, then the alternatives, each with mechanism and material) and `presentation/story.md` (one section per story, the five elements, and where in the talk it can sit). Tell the user that `structuring` places them in the outline and `scripting` writes them out.

Done when both files exist (omit one if the user wanted only a hook or only a story) and the user has confirmed them.
