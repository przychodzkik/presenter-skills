# Structuring

Produce `presentation/outline.md`: opener, body blocks, close, and a list of what was cut. Terms follow `presenting-vocabulary`; the layout is in [OUTLINE-FORMAT.md](OUTLINE-FORMAT.md). Converse and write file contents in the user's language; keep file names and section headings in English so the other skills can find them.

## 1. Gather

Read `presentation/brief.md`, `presentation/hook.md` and `presentation/story.md` when they exist. With no `presentation/brief.md`, ask at most four questions: the one-sentence core message, the audience and what they know, the talk's duration and the Q&A length, and whether the goal is to teach or persuade. Then collect the raw material: everything the user wants to say, in any order.

Done when you can state the core message, the duration, the goal and the list of raw material, and the user agrees.

## 2. Sort the material

Give every item of raw material a verdict: keep, cut, or park for later. Each keep names the part of the core message it serves; each cut and park gives a reason in one line. Ask the user about items you cannot place.

Done when every item has a verdict and a reason.

## 3. Choose body blocks

Build the body from blocks, each carrying one claim. Pick the pattern that fits the material:

- **Problem, then solution**
- **Anecdote, then lesson**
- **Case, then conclusion**
- **Data, then conclusion**
- **Thesis, then proof**
- **SCQA**: situation, complication, question, answer (craft heuristic, Minto)

For a teaching goal, order blocks so each one needs only what came before. For a persuading goal, order them from the audience's before-state toward the after-state, with the strongest block last before the close. Fewer blocks that land beat many that rush; a block needs enough minutes for its one claim.

Done when every block has a pattern, its single claim, the material it uses, and the part of the core message it serves.

## 4. Opener and close

Use the chosen hook in `presentation/hook.md` as the opener. When there is none, write "hook needed" and point to `storytelling`. Place any story from `presentation/story.md` in the block it fits. The opener and the close each state which part of the core message they serve.

The close restates the move from before-state to after-state and gives exactly one call to action that is concrete and doable by the audience.

Done when the close has exactly one call to action and the user confirms it.

## 5. Timing

Give every part minutes. The parts must add up to the duration minus Q&A.

Done when the sum matches.

## 6. Write

Write `presentation/outline.md` in the OUTLINE-FORMAT.md layout, including the cuts. Tell the user that `scripting` turns it into the full script.

Done when the file exists and the user has confirmed it.
