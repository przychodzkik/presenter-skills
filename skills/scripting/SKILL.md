# Scripting

Produce `presentation/script.md`: the full text, written for the ear. Terms follow `presenting-vocabulary`; the layout is in [SCRIPT-FORMAT.md](SCRIPT-FORMAT.md). Converse and write file contents in the user's language; keep file names and section headings in English so the other skills can find them.

## 1. Gather

Read `presentation/brief.md` (duration, core message, style notes), `presentation/outline.md`, `presentation/hook.md` and `presentation/story.md` when they exist. With an existing draft, read it instead of the outline, and add cue ids to every paragraph as SCRIPT-FORMAT.md describes. With no `presentation/outline.md` and no draft, send the user to `structuring` first.

Done when you know the duration, the style notes, the core message and the source of the structure (outline or existing draft).

## 2. Key passages

Pick the up to three passages that carry the most weight: usually the main claim of the middle block and the transition into the close. For each, offer 2–3 drafts that differ in approach, built from the user's material. Revise with the user.

The chosen hook and stories are used as given: the spoken text from `hook.md` and `story.md` goes in unchanged, and you write only the connections around it.

Done when the user has picked one version of every key passage.

## 3. Write for the ear

Write the whole script, applying these rules to every paragraph:

- **Short spoken sentences**, one idea each, in plain words.
- **Ladder of abstraction** (craft heuristic): replace each abstract claim with a concrete example, number or image. When the user has not supplied one, mark `[needs example]` and never invent one.
- **Analogy**: explain each new idea by pointing to something the audience already knows.
- **Cause**: say why one thing follows another, with "because" or "so", rather than listing facts side by side.
- **One name per idea**; define or cut jargon, because experts forget what they know (curse of knowledge, research-backed).
- **Style notes**: follow the brief's wording about length, register and tone. A named speaker is a source of traits to reproduce, and another speaker's phrases are never copied.

Done when every paragraph passes each rule or carries a marker listing what is missing.

## 4. Length

Compare the script to the duration minus Q&A at about 130 words per minute (craft heuristic; faster or slower speakers adjust). Trim or extend until within ten percent, or until the user accepts the difference.

Done when the word count and the target are stated and the gap is within ten percent or accepted.

## 5. Read aloud

Ask the user to read the script aloud and mark where they stumble, run out of breath or lose the thread. Revise those places.

Done when the user has read it aloud and the marked places are fixed, or the user has declined.

## 6. Write

Write `presentation/script.md` in the SCRIPT-FORMAT.md layout and list every `[needs example]` still open. Tell the user that `slide-plan` plans the live slides from it and `slidedoc` builds a reading version.

Done when the file exists and the user has confirmed it.
