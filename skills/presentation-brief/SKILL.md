# Presentation brief

Interview until the brief is complete, then write it. Terms follow `presenting-vocabulary`. The layout of `presentation/brief.md` is in [BRIEF-FORMAT.md](BRIEF-FORMAT.md).

Do not draft a hook, outline, script or slides here. The brief is the only output.

## 1. Take stock

Read the user's message, any files they point to, and `presentation/brief.md` if it exists. Mark each field of BRIEF-FORMAT.md as answered or open. Material in files is read by you, never requested from the user.

Done when every field is marked, with each answered field traceable to something the user gave.

## 2. Interview

Ask only about open fields; anything already answered stays unasked. Ask in rounds of at most four questions. Number each, say why it matters in half a sentence, and offer your recommended answer so the user can reply "yes". Group by theme, in this order:

1. **Occasion**: duration, live or online, room size, interruptions, atmosphere, who speaks around them.
2. **Audience**: who they are, what they know, what they know about the speaker, what they believe or fear.
3. **Payoff**: the before-state, the after-state, teach or persuade.
4. **Speaker's wishes**: what they want to share, how they imagine the start and the end, and their style preferences in their own words (long or short, simple or sophisticated, tone, a speaker whose manner they like).

For a style reference that names a speaker, ask what exactly the user likes about that manner and record those traits.

Done when no field is open, or the user has said they can't answer it yet and it is recorded as open with what is needed.

## 3. Core message

Propose one sentence that the whole talk reduces to, built from the payoff and the speaker's wishes. Revise until the user confirms it.

Done when the user has confirmed the exact sentence.

## 4. Write the brief

Write `presentation/brief.md` using BRIEF-FORMAT.md, keeping the user's own phrasing in Style notes. Show the user a five-line summary and ask what is wrong.

Done when the file exists, the user has confirmed the summary, and the reply names the next skills: `storytelling` for a hook or story, `structuring` for an outline.
